## Discovery notes

- Existing Laravel code already contains partial services, models, migrations, and non-versioned routes. These should be extended or wrapped under `/api/v2`, leaving the existing routes intact.
- Existing clients still depend on Supabase edge functions for payment, order processing, wallet funding, delivery, push, and Buy For Me. No frontend or production Supabase changes are part of this phase.
- Existing Laravel wallet migrations need reconciliation with the V2 contract: transaction `type` must be `credit|debit`; category must be nullable and limited to `order_payment|refund|reversal|admin_credit`; wallet top-up uses credit/null category/null direction/completed status.
- Full request/response examples should be added beside each endpoint as the corresponding Form Request, Resource, and feature test is implemented.
